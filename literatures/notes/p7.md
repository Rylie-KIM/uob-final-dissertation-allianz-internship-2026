## 🇰🇷 한국어 요약

### 1. 문제 정의 — 프로그램 평가의 계량경제학

Imbens & Wooldridge (2009)는 **처리(treatment)가 결과(outcome)에 미치는 인과 효과**를 비실험(관측) 데이터에서 추정하는 방법론을 체계적으로 정리한다. 노동시장 훈련 프로그램을 주요 예시로 사용하지만, 모든 방법이 도메인 독립적이며 보험 조사 개입에 직접 적용된다.

핵심 문제 의식: 처리를 받는 개인은 받지 않는 개인과 **체계적으로 다르다** (자기 선택 편향, self-selection). 이를 보정하지 않으면 인과 효과가 아니라 선택 편향이 추정된다. 논문은 이 문제를 해결하는 다섯 가지 접근법을 포함한다: (1) 무작위 실험, (2) 무교란성 기반 방법(회귀, 매칭, IPW), (3) IV, (4) RDD, (5) DiD.

### 2. 핵심 기술 개념과 수식

#### 2-1. Rubin 인과 모델 (RCM) — 잠재적 결과

개인 i에 대해 두 개의 잠재적 결과:
- Y_i(0): 처리 미참여시 결과
- Y_i(1): 처리 참여시 결과
- 실제 관측 결과: Y_i = Y_i(W_i) where W_i ∈ {0,1}

**주요 estimand들:**

Population Average Treatment Effect (PATE):
$$\tau_{\text{pate}} = \mathbb{E}[Y_i(1) - Y_i(0)]$$

Average Treatment Effect on the Treated (PATT):
$$\tau_{\text{patt}} = \mathbb{E}[Y_i(1) - Y_i(0) | W_i = 1]$$

Conditional ATE (CATE):
$$\tau_{\text{cate}} = \frac{1}{N} \sum_{i=1}^{N} \mathbb{E}[Y_i(1) - Y_i(0) | X_i]$$

#### 2-2. 무교란성(Unconfoundedness) 가정

**가정 1 (무교란성 / Unconfoundedness)**:
$$W_i \perp\!\!\!\perp \left(Y_i(0), Y_i(1)\right) \mid X_i$$

관측된 공변량 X_i를 조건으로 처리 배정이 잠재적 결과와 독립. "선택은 관측 변수로 설명된다"는 가정. Rosenbaum & Rubin(1983)이 "강한 무시가능성(strong ignorability)"이라 명명.

**가정 2 (중첩, Overlap)**:
$$0 < \text{pr}(W_i = 1 | X_i = x) < 1 \quad \text{for all } x$$

모든 공변량 값에 대해 처리군과 대조군 모두 존재. 무교란성과 중첩을 합쳐 강한 무시가능성.

#### 2-3. 역확률 가중치 (IPW) 추정량

성향 점수 e(x) = Pr(W_i = 1|X_i = x)를 이용한 IPW 추정량:

$$\tau_{\text{pate}} = \mathbb{E}\left[\frac{W_i \cdot Y_i}{e(X_i)} - \frac{(1-W_i) \cdot Y_i}{1 - e(X_i)}\right] \tag{16}$$

표본 버전 (식 17):
$$\hat{\tau}_{\text{weight}} = \frac{1}{N} \sum_{i=1}^{N} \left[\frac{W_i \cdot Y_i}{\hat{e}(X_i)} - \frac{(1-W_i) \cdot Y_i}{1 - \hat{e}(X_i)}\right]$$

실제 사용하는 정규화된 IPW 추정량 (식 18):
$$\hat{\tau}_{\text{ipw}} = \sum_{i=1}^{N} \frac{W_i \cdot Y_i}{\hat{e}(X_i)} \bigg/ \sum_{i=1}^{N} \frac{W_i}{\hat{e}(X_i)} - \sum_{i=1}^{N} \frac{(1-W_i) \cdot Y_i}{1-\hat{e}(X_i)} \bigg/ \sum_{i=1}^{N} \frac{1-W_i}{1-\hat{e}(X_i)}$$

#### 2-4. 이중차분법 (Difference-in-Differences, DiD)

두 집단(처리군 t, 대조군 c)과 두 기간(처리 전 pre, 처리 후 post)의 데이터를 이용:

$$\hat{\tau}_{\text{DiD}} = (\bar{Y}_{t,\text{post}} - \bar{Y}_{t,\text{pre}}) - (\bar{Y}_{c,\text{post}} - \bar{Y}_{c,\text{pre}})$$

**병행 추세 가정 (Parallel Trends)**:

$$\mathbb{E}[Y_i(0)_{post} - Y_i(0)_{pre} | W_i = 1] = \mathbb{E}[Y_i(0)_{post} - Y_i(0)_{pre} | W_i = 0]$$

"처리가 없었다면 처리군도 대조군과 같은 추세로 변화했을 것"이라는 가정. 이를 위반하면 DiD 추정량이 편향됨.

회귀 형태 (표준 구현):
$$Y_{it} = \alpha + \beta \cdot W_i + \gamma \cdot T_t + \delta \cdot (W_i \times T_t) + \varepsilon_{it}$$

δ가 DiD 추정량 τ_{DiD}.

#### 2-5. 회귀 불연속 설계 (Regression Discontinuity Design, RDD)

처리 배정이 연속형 변수 R_i (running variable)의 임계값 c를 기준으로 결정될 때:

$$W_i = \mathbf{1}[R_i \geq c]$$

Local Average Treatment Effect (LATE) at the threshold:

$$\tau_{\text{RDD}} = \lim_{r \downarrow c} \mathbb{E}[Y_i | R_i = r] - \lim_{r \uparrow c} \mathbb{E}[Y_i | R_i = r]$$

연속성 가정: E[Y_i(0)|R_i = r]과 E[Y_i(1)|R_i = r]이 r에서 연속. RDD는 임계값 근방에서만 유효한 LATE를 추정한다.

**Fuzzy RDD**: 임계값이 배정을 결정하지만 완벽하지 않을 때:
$$\tau_{\text{fuzzy}} = \frac{\lim_{r \downarrow c} \mathbb{E}[Y_i|R_i=r] - \lim_{r \uparrow c} \mathbb{E}[Y_i|R_i=r]}{\lim_{r \downarrow c} \mathbb{E}[W_i|R_i=r] - \lim_{r \uparrow c} \mathbb{E}[W_i|R_i=r]}$$

분모는 임계값 근방에서 처리 확률의 점프.

#### 2-6. 정규화 차이 (Normalized Difference) — 공변량 균형 점검

처리군과 대조군 간 공변량 차이를 표본 크기와 무관하게 측정:

$$\Delta_X = \frac{\bar{X}_1 - \bar{X}_0}{\sqrt{S_0^2 + S_1^2}} \tag{3}$$

Imbens & Rubin (2007)의 경험 법칙: **|Δ_X| > 0.25이면 선형 회귀 추정이 스펙을 민감하게 타는 경고 신호**.

#### 2-7. 매칭 (Matching) 추정량

각 처리된 단위 i에 대해 가장 가까운 M개의 대조군을 찾아 반사실 결과를 대체:

$$\hat{Y}_i(0) = \begin{cases} Y_i & \text{if } W_i = 0 \\ \frac{1}{M} \sum_{j \in \mathcal{J}_M(i)} Y_j & \text{if } W_i = 1 \end{cases}$$

매칭 추정량 (식 19):
$$\hat{\tau}_{\text{match}} = \frac{1}{N} \sum_{i=1}^{N} \left(\hat{Y}_i(1) - \hat{Y}_i(0)\right)$$

#### 4-1. DiD를 Allianz 사기 탐지에 적용 — Build 04

**처리 정의**: 특정 시점 t*에 사기 탐지 모델 버전이 v1 → v2로 변경됨 (모델 임계값 또는 알고리즘 변경).

**집단 정의**:
- 처리군 (W=1): 모델 v2 배포 이후 처리된 클레임 세그먼트
- 대조군 (W=0): 모델 변경의 영향을 덜 받는 세그먼트 (예: 다른 product_line 또는 지역)

**DiD 공식 (Allianz 버전)**:
$$\hat{\tau}_{\text{DiD}} = (\bar{\text{fraud\_rate}}_{v2\text{ 세그먼트, post}} - \bar{\text{fraud\_rate}}_{v2\text{ 세그먼트, pre}}) - (\bar{\text{fraud\_rate}}_{\text{control, post}} - \bar{\text{fraud\_rate}}_{\text{control, pre}})$$

**병행 추세 검증**: v2 배포 전 두 세그먼트의 사기율 추세가 평행한지 `claim_date` 기준으로 시각화 및 검증.

`intervention_analysis.py` 구현:

```python
# DiD 회귀 형태
import statsmodels.formula.api as smf
model = smf.ols(
    "fraud_label ~ C(post) + C(treated) + C(post):C(treated)",
    data=df
).fit()
tau_did = model.params["C(post)[T.1]:C(treated)[T.1]"]
```

#### 4-2. RDD를 모델 점수 임계값에 적용 — Build 04

**Running variable**: `model_v1_score` (또는 v2_score)
**Threshold c**: 조사 여부를 결정하는 임계 점수 (예: 0.5)
**처리 W_i**: investigated = 1 if score ≥ 0.5

RDD는 "임계값 근방에서 점수 c±ε인 클레임들은 사실상 유사하다"는 가정 하에 임계값 근방의 LATE를 추정한다:

$$\tau_{\text{RDD}} = \lim_{s \downarrow c} E[\text{fraud\_label} | \text{score} = s] - \lim_{s \uparrow c} E[\text{fraud\_label} | \text{score} = s]$$

**핵심 시사점**: RDD는 **임계값 조작(manipulation) 여부 확인**이 필요. McCrary 검정으로 running variable 밀도가 임계값에서 불연속인지 확인. SFP 루프에서 모델이 동일 점수를 반복 학습하면 임계값 근방에 점수가 과도하게 집중될 수 있다.

```python
# RDD: 국소 선형 회귀로 임계값 좌우 추정
from scipy.stats import linregress
left  = df[df['score'] < c]
right = df[df['score'] >= c]
left_fit  = smf.ols("fraud_label ~ score", data=left).fit()
right_fit = smf.ols("fraud_label ~ score", data=right).fit()
tau_rdd = right_fit.params['Intercept'] - left_fit.params['Intercept']
```

#### 4-3. 매칭과 IPW를 SFP 진단에 적용 — Build 03 + Build 04

**성향 점수 추정**: `model_v1_score`가 조사(investigation) 여부를 결정하는 메인 드라이버. 추가 공변량으로 `amount`, `postcode_risk`, `prior_claims`, `claim_type` 포함.

```python
from sklearn.linear_model import LogisticRegression
propensity_model = LogisticRegression()
propensity_model.fit(X, df['investigated'])
e_hat = propensity_model.predict_proba(X)[:, 1]

# IPW 추정량 (식 18)
ipw_treated   = (df['investigated'] * df['fraud_label'] / e_hat).sum() / (df['investigated'] / e_hat).sum()
ipw_control   = ((1-df['investigated']) * df['fraud_label'] / (1-e_hat)).sum() / ((1-df['investigated']) / (1-e_hat)).sum()
tau_ipw       = ipw_treated - ipw_control
```

### 5. 한계 (논문이 명시)

- **병행 추세 가정 (DiD)**: 검정 불가. 처리 전 기간의 평행성으로 타당성을 부분적으로 확인할 뿐. Allianz에서 모델 버전 교체와 동시에 규제 변화나 시장 충격이 있었다면 위반 가능.
- **연속성 가정 (RDD)**: 임계값 근방에서만 유효. 임계값에서 멀리 떨어진 클레임에 대한 외삽은 신뢰 불가. Allianz에서 점수 조작(score manipulation — 사기꾼이 임계값 아래로 점수를 낮추도록 행동 수정)이 있으면 running variable 연속성 위반.
- **무교란성 가정 (IPW, 매칭)**: 미관측 혼란변수(조사관의 현장 판단 U)가 있으면 모든 조정 기반 방법이 편향됨. 민감도 분석(Rosenbaum bounds) 필요.
- **오버랩 부족**: 점수가 극단(0 또는 1)에 몰릴 때 IPW 가중치가 폭발적으로 커짐. 클리핑(trimming) 또는 오버랩 가중치로 대응.

## 🇬🇧 English Summary

### 1. Problem — Estimating Causal Effects of Treatments from Observational Data

Imbens & Wooldridge (2009) survey the modern econometrics toolkit for program evaluation — the problem of estimating the causal effect of a policy or treatment when randomisation is infeasible. The central challenge is **selection bias**: treated and untreated units differ systematically before treatment, so naive comparisons of outcomes are confounded.

The paper covers five identification strategies in depth: randomised experiments (Section 4), unconfoundedness-based methods (Section 5), instrumental variables (Section 6), regression discontinuity designs (Section 6), and difference-in-differences (Section 6). Sections 5 is the most directly relevant to Builds 03 and 04.

### 2. Key Technical Contributions

#### 2-1. Rubin Causal Model

The RCM framework (Rubin, 1974; tracing to Neyman, 1923) defines causal inference as the comparison of potential outcomes Y_i(1) and Y_i(0) for the same unit. Only one can be observed — the fundamental problem. The paper defines four estimands:

- PATE: τ_pate = E[Y_i(1) − Y_i(0)]
- PATT: τ_patt = E[Y_i(1) − Y_i(0) | W_i = 1]
- CATE: τ_cate = (1/N) Σ E[Y_i(1) − Y_i(0) | X_i]
- CATT: average over treated subsample

#### 2-2. Unconfoundedness and Overlap

The two key identification assumptions (§5.1):

**Assumption 1 (Unconfoundedness):**
$$W_i \perp\!\!\!\perp (Y_i(0), Y_i(1)) \mid X_i$$

**Assumption 2 (Overlap):**
$$0 < \text{pr}(W_i = 1 | X_i = x) < 1 \quad \forall x$$

Together, these constitute Rosenbaum & Rubin's (1983) strong ignorability. The combination allows identification of τ(x) = E[Y_i(1) − Y_i(0) | X_i = x] from observational data.

#### 2-3. IPW Estimator (Equations 16–18)

The normalised IPW estimator achieves the semiparametric efficiency bound (Hirano, Imbens and Ridder, 2003) when the propensity score is estimated via a logistic sieve:

$$\hat{\tau}_{\text{ipw}} = \sum_i \frac{W_i Y_i}{\hat{e}(X_i)} \bigg/ \sum_i \frac{W_i}{\hat{e}(X_i)} - \sum_i \frac{(1-W_i)Y_i}{1-\hat{e}(X_i)} \bigg/ \sum_i \frac{1-W_i}{1-\hat{e}(X_i)}$$

#### 2-4. Difference-in-Differences

The DiD estimator:

$$\hat{\tau}_{\text{DiD}} = (\bar{Y}_{t,\text{post}} - \bar{Y}_{t,\text{pre}}) - (\bar{Y}_{c,\text{post}} - \bar{Y}_{c,\text{pre}})$$

requires the **parallel trends assumption**: in the absence of treatment, the treated group's outcome would have followed the same trend as the control group. This is not directly testable but can be partially validated by inspecting pre-treatment trends. Bertrand, Duflo and Mullainathan (2004) show that serial correlation in DiD can severely understate standard errors — cluster-robust SEs are recommended.

#### 2-5. Regression Discontinuity Design

For sharp RDD where W_i = 1[R_i ≥ c]:

$$\tau_{\text{RDD}} = \lim_{r \downarrow c} E[Y_i|R_i=r] - \lim_{r \uparrow c} E[Y_i|R_i=r]$$

Implemented via local linear regression with a bandwidth h chosen by cross-validation (IK bandwidth selector of Imbens & Kalyanaraman, 2009). The McCrary (2008) density test checks that the running variable density is continuous at c — discontinuity implies manipulation.

#### 2-6. Matching

The Abadie-Imbens (2006) matching estimator (equation 19) is unbiased of order O(N^{-1/K}) where K is covariate dimension. Key recommendation: combine matching with regression adjustment (§5.8) to remove residual covariate imbalance within matched pairs. The doubly-robust estimator (§5.6) that combines IPW with regression is preferred in practice.

### 3. Direct Relevance to the Allianz SFP Project

#### 3-1. DiD Applied to Model Version Changes — Build 04

**Treatment event**: Deployment of model v2 (change in fraud score algorithm or threshold) at time t*.

**Groups**:
- Treated: claim segments heavily reliant on model v2's changed features
- Control: segments with stable scoring across versions (different `product_line` or `claim_type`)

**DiD estimate** of model change impact on fraud discovery rate:

$$\hat{\tau}_{\text{DiD}} = (\bar{Y}_{v2\text{ seg, post}} - \bar{Y}_{v2\text{ seg, pre}}) - (\bar{Y}_{\text{ctrl, post}} - \bar{Y}_{\text{ctrl, pre}})$$

This removes time-period shocks (e.g., seasonal fraud patterns) and group-level fixed effects (e.g., structural differences between claim types) to isolate the model change effect.

#### 3-2. RDD Applied to Investigation Score Threshold — Build 04

The fraud triage system uses a **threshold on model_v1_score** (e.g., 0.5) to determine investigation. This is exactly the sharp RDD setting:

- Running variable R_i = `model_v1_score`
- Cutoff c = investigation threshold
- Treatment W_i = `investigated`
- Outcome Y_i = `fraud_label`

The RDD LATE answers: "What is the causal effect of being investigated for claims right at the score boundary?" This is the most credible estimate of investigation's causal effect because claims just above and just below c are near-identical in all other respects.

**SFP implication**: The RDD running variable density test (McCrary test) can detect whether the SFP loop is causing score manipulation — if successive model versions push more claims toward particular score ranges, the density will show discontinuities.

### 4. Limitations

- **Parallel trends (DiD)**: Untestable. Pre-period trend tests provide partial reassurance only.
- **Continuity (RDD)**: Local validity only — estimates do not generalise away from the threshold.
- **Unconfoundedness (IPW/matching)**: Fails if investigator judgment (U) is not captured by observed covariates.
- **Overlap violations**: Extreme propensity scores cause explosive IPW weights; trimming required.

## 🎯 Interview Talking Points (P7-specific)

| Prompt | Use P7 to say… |
|--------|---------------|
| *"How do you estimate the causal effect of investigation on fraud discovery at Allianz?"* | "I use three complementary quasi-experimental methods from Imbens & Wooldridge (2009). First, IPW: I estimate the propensity to be investigated given the model score and claim features, then use inverse-probability weights to get a bias-corrected fraud rate. Second, DiD: I compare fraud discovery rates before and after a model version change between affected and unaffected claim segments. Third, RDD: I exploit the fact that investigation is triggered by a score threshold — claims just above and below that threshold are nearly identical, so the discontinuity in fraud discovery at the threshold estimates the causal effect." |
| *"What is the parallel trends assumption and how do you test it?"* | "Parallel trends requires that in the absence of the model change, fraud discovery rates in the treated and control segments would have moved in the same direction. I test this by plotting fraud rates by quarter for both groups for the two years before the model change — if the trends are roughly parallel, the assumption has empirical support. Bertrand, Duflo and Mullainathan (2004) warn that DiD standard errors can be understated with serial correlation, so I use cluster-robust SEs grouped by claim_type." |
| *"Why use RDD rather than a simple before-after comparison?"* | "A simple before-after confounds any model change with seasonal fraud patterns and macroeconomic trends. RDD exploits a sharper discontinuity: claims just above the investigation threshold should be identical to those just below it — same amount, same postcode risk, same prior claims — the only difference is that one gets investigated. This near-randomisation at the threshold gives a credible local average treatment effect without needing parallel trends." |
| *"What is the McCrary test and why does it matter for the SFP loop?"* | "The McCrary (2008) density test checks whether the running variable — the fraud score — has a smooth density at the investigation threshold, or a sudden jump. A jump suggests that claims are being manipulated to fall just below the threshold, avoiding investigation. In the SFP context, if the model repeatedly under-investigates certain score ranges, fraudsters learn this and concentrate there. A discontinuity in the McCrary test is therefore a direct diagnostic signal of SFP-induced adversarial adaptation." |
| *"How do you handle the overlap problem in your IPW estimates?"* | "When model scores cluster near 0 or 1, the IPW weights blow up. I follow Imbens & Wooldridge's recommendation (§5.10) to trim observations with estimated propensity scores outside [0.1, 0.9], and report the average treatment effect for the trimmed subsample — τ_{cate,A} in their notation. I also plot the distribution of scores by investigation status to visually confirm overlap." |
| *"What is the normalized difference and how do you use it in Build 02?"* | "The normalized difference Δ_X = (X̄₁ − X̄₀) / √(S₀² + S₁²) measures covariate imbalance between investigated and uninvestigated claims in a scale-free way. Imbens and Rubin's rule of thumb is that |Δ_X| > 0.25 signals that regression estimates will be sensitive to model specification. In Build 02, I track Δ_X across model versions: if the SFP loop is running, the balance between investigated and uninvestigated claims deteriorates over time — Δ_X grows — which is a quantitative SFP detection signal." |
| *"What is the doubly-robust estimator and do you use it?"* | "The doubly-robust estimator (Robins & Rotnitzky, 1995; §5.6 of Imbens & Wooldridge) combines IPW with regression adjustment. It is consistent if either the propensity score model or the outcome model is correctly specified — not necessarily both. I implement it in Build 06 via DoWhy's `backdoor.linear_regression` as a sensitivity check against the pure IPW estimate." |
| *"How does your Build 04 analysis relate to a policy recommendation for Allianz?"* | "The DiD and RDD estimates answer: 'Does investigation actually reduce fraud incidence, or does the model just flag already-detectable fraud?' If the treatment effect is large and positive, more investigation is justified. If it's near zero, the model is just labelling claims the system would have caught anyway — and the SFP loop is self-confirming rather than genuinely effective. The RDD result near the threshold is also directly actionable: it tells the operations team whether raising or lowering the investigation threshold by a few score points would meaningfully change fraud discovery." |
