## 🇰🇷 한국어 요약

### 1. 문제 정의 — 데이터 마이닝 기반 사기 탐지의 종합 조사

Phua et al. (2010) 은 자동화된 사기 탐지에 관한 거의 모든 학술 논문과 리뷰 논문을 정리한 **포괄적 서베이**다. 세 가지 주요 목적:

1. **사기꾼(fraudster) 분류** — 누가 사기를 치는가? 직업적 범죄자부터 기회주의적 개인까지.
2. **데이터 유형과 탐지 방법 분류** — 어떤 데이터를 어떤 방법으로 분석하는가?
3. **관련 도메인(테러 탐지, 금융 범죄, 침입 탐지)과의 크로스오버** — 다른 분야에서 무엇을 배울 수 있는가?

**핵심 통찰**: 보험, 신용카드, 통신 등 모든 사기 탐지 도메인에서 공통적으로 나타나는 두 가지 근본 문제:
- **데이터 불균형**: 실제 사기 비율은 0.1% ~ 10%에 불과 (Fig. 3.2)
- **샘플 선택 편향(selective labeling)**: 조사된 사례에만 라벨이 존재

이 두 문제가 결합하면 사기 탐지 모델이 **자신이 찾으려는 사기만 찾는** 자기강화 편향이 발생한다 — 이것이 SFP 루프의 도메인 표현이다.

### 2. 핵심 기술 개념

#### 2-1. 사기꾼 분류 체계 (Fig. 2.1)

```
Fraudster
├── Manager (고위직 내부자 사기 — 재무보고 조작)
├── Employee (직원 사기 — 소매 거래, 내부 데이터 오용)
└── External
    ├── Average Offender (평균 범죄자 — 기회주의적, 무작위적, 계절적)
    ├── Criminal Offender (직업 범죄자 — 조직화, 개인 신원 위장)
    └── Organised Crime (조직 범죄 — 광범위한 네트워크, 탐지 시스템 역공학)
```

**SFP 루프와의 관련성:**
- **평균 범죄자**: 모델이 탐지하기 쉬움. SFP 루프의 초기 단계에서 과잉 탐지됨.
- **직업/조직 범죄자**: 탐지 시스템을 역공학하여 점수를 임계값 아래로 유지. SFP 루프가 진행될수록 이들만 남음 → **빙산의 일각 문제 심화**.

#### 2-2. 영향을 받는 산업과 보험 사기의 특수성 (§2.2)

Fig. 2.2: 51개 고유 논문 중 사기 유형별 분포. 보험 사기는 네 가지 하위 유형:
- **주택보험** (home insurance): 과도한 청구, 허위 분실 신고
- **자동차보험 (automobile insurance)**: 사고 위장, 부상 과장 (Allianz의 직접 도메인)
- **농작물보험** (crop insurance): 계절성 조작
- **의료보험** (medical insurance): 청구 코드 조작

**자동차 보험 데이터 특성** (논문 직접 기술):
- 속성: 사고, 청구인, 운전자, 부상, 치료, 손실임금, 차량, 기타 카테고리를 나타내는 이진 지시변수
- Phua et al. (2004)의 자동차 보험 데이터셋이 공개 데이터 중 드물게 사용 가능한 것으로 명시됨

#### 2-3. 데이터 유형과 측정 (§3) — "빙산의 일각" 문제

**Fig. 3.2**: 19개 논문의 사기 비율 분석:
- 신용카드/보험: 0.1% ~ 10% 사기 비율
- 80% 이상의 논문이 30% 미만 사기율 데이터 사용
- **핵심 문제**: 관측된 사기율은 진짜 사기율을 심각하게 과소추정

논문이 명시적으로 지적하는 세 가지 데이터 문제 (§4.1 Fig. 4.1):
- **Volume 변동**: 사기와 합법 클래스 모두 독립적으로 변화 → 클래스 분포가 시간에 따라 변함
- **Multiple fraud styles**: 여러 사기 유형이 동시 발생. 각기 규칙적, 계절적, 일회성 패턴
- **Class label 부정확성**: 라벨이 잘못되거나 선택 편향에 노출 (Hand, 2004; Brockett, 2002)

이것이 **SFP 루프의 도메인 메커니즘**이다: 조사된 사례에만 라벨이 있으므로, 모델은 자신의 선택 결과만을 보면서 학습한다.

#### 2-4. 성과 지표 (§3.2) — 사기 탐지 평가의 특수성

논문이 강조하는 핵심 지적:

> "보험 사기 탐지에서 오류 비용(false positive vs false negative)은 불균등하고, 불확실하고, 사례마다 다를 수 있으며, 시간에 따라 변할 수 있다."

권장 지표:
- **비용-편익 모델** (cost-benefit matrix): 단순 정확도 대신 금전적 비용 반영
- **AUC (Area Under Curve)**: 임계값 독립적 평가. Viaene et al. (2004)만이 AUC를 극대화한 단일 자동차 보험 연구
- **AMOC (Activity Monitoring Operating Characteristic)**: 신용카드 사기의 시계열 평가에 적합
- **True Positive Rate (실제 사기 탐지율)**: `fraud_label = 1` 중 탐지 비율 — SFP 루프에서 이것이 과대추정됨

**SFP 루프와의 관련성**: 표준 정확도 지표가 SFP 루프를 탐지하지 못하는 이유는, 평가 데이터 자체가 모델이 이미 본 영역(investigated=1)에서만 라벨이 있기 때문이다.

#### 2-5. 탐지 방법론 분류 (§4) — 네 가지 데이터 범주

| 데이터 유형 | 방법론 범주 | 대표 기법 |
|-----------|-----------|---------|
| A: 라벨 있는 사기+합법 | 지도 학습 | Logistic regression, SVM, Neural Net, Decision Tree |
| B: 라벨 있는 합법만 | 준지도 학습 | Anomaly detection, one-class SVM |
| C: 라벨 없음 | 비지도 학습 | Clustering (k-means), outlier detection |
| E: 평가 인스턴스 (라벨 없음) | 예측 대상 | - |

**A+B+C+D** (지도+비지도 하이브리드)가 일반적으로 최고 성능.

주요 지도 학습 결과:
- **Viaene et al. (2004)**: 자동차 보험에 부스팅된 순진한 베이즈 (AdaBoosted Naive Bayes)로 AUC 극대화
- **Belhadji et al. (2000)**: 프로빗 회귀로 가장 중요한 변수 선택 후 임계값 최적화
- **Artis et al. (1999)**: 다항 로짓 모델(MNL)과 중첩 다항 로짓(NMNL)을 자동차 보험에 적용

#### 2-6. 자동차 보험 사기의 특수 평가 기준 (§3.2 후반)

논문이 자동차 보험에 특화된 평가 이슈를 지적:

- **Von Altrock (1995)**: 자신들의 퍼지 로직 알고리즘이 경험 많은 사기 조사관보다 약간 더 나은 성능이라고 주장
- **Brockett et al. (2002)와 Stefano & Gisella (2001)**: 인간 전문가와의 비교 성능을 언급하지만, 실제 검증은 인간 판단과 자동화 방법이 **보완적**
- **Williams (1999)**: 사기 전문가가 규칙을 탐색하고 발전시키는 역할의 중요성 강조

**SFP 루프 함의**: 알고리즘이 인간 조사관을 대체할수록 인간의 Z(현장 판단)가 더 이상 데이터에 포함되지 않고, 모델은 자신이 생성한 편향된 라벨만을 학습한다.

#### 2-7. 방법론 비판 (§4.6) — 논문의 핵심 비판 목록

논문이 직접 나열하는 현 사기 탐지 연구의 한계:

1. "운영 환경에서 처리 속도가 중요한데, 복잡한 비선형 지도 모델(SVM, NN)은 느리다"
2. "개념 표류(concept drift) — 사기 패턴이 시간에 따라 변함"
3. "오직 7개 연구만이 실제 배포 시스템을 구현했거나 구현된 것으로 알려져 있다"
4. "시간적 정보를 명시적으로 활용하는 연구가 거의 없다"
5. "공간적(spatial) 정보를 활용하는 연구가 전혀 없다"

이 비판들이 Allianz 연구의 동기: SFP 루프는 개념 표류의 한 원인이며, 시간적 정보가 핵심이다.

### 4. Allianz SFP 연구와의 직접 연관성

이 논문이 **연구의 도메인 컨텍스트 전체를 제공**하며, SFP 루프가 발생하는 구체적 메커니즘을 사기 탐지 문헌에서 식별한다.

#### 4-1. "빙산의 일각" 문제와 SFP 루프의 관계

**빙산 은유**: 관측된 사기(조사되고 발견된 사기)는 전체 사기의 일부에 불과. 대부분의 사기는 조사되지 않아 라벨이 없다.

SFP 루프는 이 빙산을 **더 작게 만든다**:
- v1 모델 → 특정 패턴의 클레임만 조사 → 해당 패턴에서만 사기 발견
- v2 모델은 v1이 발견한 패턴만 학습 → 더 좁은 범위만 조사
- v3 모델은 더욱 좁아짐...

**수식화**:

관측된 사기율 (편향된 추정):
$$\hat{p}_{\text{observed}} = \frac{\text{discovered fraud}}{\text{investigated claims}} = P(\text{fraud} | \text{investigated})$$

진짜 사기율 (알 수 없음):
$$p_{\text{true}} = P(\text{fraud}) = P(\text{fraud}|\text{investigated}) \cdot P(\text{investigated}) + P(\text{fraud}|\text{not investigated}) \cdot P(\text{not investigated})$$

SFP 루프가 진행될수록 P(investigated|not fraud) 증가 → P(fraud|investigated) 과대추정 → 모델 "성능"이 허수로 좋아 보임.

#### 4-4. 조직 범죄와 SFP 루프의 상호작용 — 핵심 인사이트

논문이 지적하는 조직 범죄의 특성 (§2.1):
> "직업 사기꾼과 조직 범죄 집단은 **반복적으로 자신의 신원을 위장하고 탐지 시스템에 적응하기 위해 운영 방식(modus operandi)을 변경**한다. 따라서 탐지 시스템 알고리즘과 직업 사기꾼의 운영 방식 간의 전략적 상호작용을 고려하는 것이 중요하다."

이것이 SFP 루프의 **적대적(adversarial) 차원**이다:
- SFP 루프 → 특정 패턴만 조사됨
- 조직 범죄 → 조사받지 않는 패턴으로 이동
- 모델 → 이동한 패턴을 학습하지 못함
- SFP 루프 가속

**Build 05의 랜덤화 전략이 이 문제에 직접 대응**: ε-greedy는 탐지 알고리즘에 예측 불가능성을 도입하여 사기꾼의 적응을 어렵게 한다.

#### 4-5. 공개 데이터셋 가용성 문제

논문은 보험 사기 탐지 연구의 가장 큰 실용적 장애물 중 하나로 **공개 데이터의 부재**를 지목:

> "사기 탐지를 위해 공개적으로 사용 가능한 데이터셋은 없다. 단, Phua et al. (2004)의 비교적 작은 자동차 보험 데이터셋만 예외."

이것이 **합성 데이터 생성 (Build 00 + Build 01)의 정당화**다. 논문의 §3.1은 합성 데이터가:
- 알려진 사기의 변형을 생성하고
- 시스템 벤치마킹에 사용되며
- 실제 데이터의 합리적 대안임을 확인 (Barse et al., 2003)

### 5. 한계 (논문이 명시)

- **방법론 편향**: 논문은 복잡한 비선형 모델(SVM, NN)에 대한 연구가 과도하게 많고, 장기적으로 단순한 Naive Bayes, Logistic Regression이 동등하거나 더 나은 성능을 보일 수 있다고 지적.
- **시간적 정보 미활용**: "시간적 정보를 명시적으로 활용하는 연구가 거의 없다" — 이것이 SFP 루프 탐지의 핵심 공백.
- **실제 배포 사례 부족**: 51개 논문 중 실제 배포된 시스템은 7개뿐.
- **2010년 이후 갱신 부재**: 딥러닝, 그래프 신경망, LLM 기반 탐지는 다루지 않음.
- **Allianz 한계**: 영국 자동차 보험의 특수 규제 환경(FCA 소비자 의무)은 논문이 다루는 호주/미국 중심 연구와 다를 수 있음.

## 🇬🇧 English Summary

### 1. Problem — The State of Data Mining-Based Fraud Detection

Phua et al. (2010) is the definitive survey of automated fraud detection across all data mining techniques, covering 51 unique published fraud detection papers across credit card, insurance, telecommunications, and internal fraud. The paper serves three roles for the Allianz dissertation: (1) it taxonomises the problem domain; (2) it identifies the "tip-of-the-iceberg" problem as a systematic bias; and (3) it documents the absence of publicly available insurance data, justifying synthetic data generation.

### 2. Key Technical Contributions

#### 2-1. Fraudster Taxonomy (Figure 2.1)

Three external fraud profiles directly relevant to the SFP loop:
- **Average offenders**: Opportunistic, random, detectable. The SFP loop over-investigates this group in early model versions.
- **Criminal offenders**: Professional, identity-disguising, adaptive. As the loop progresses, these remain undetected because they learn to stay below the investigation threshold.
- **Organised crime**: Network-scale, counter-intelligence capable. Explicitly reverse-engineer detection systems — the adversarial dimension of the SFP loop.

#### 2-2. The "Tip of the Iceberg" Problem

Key insight from §3 and §4.1:

Labels (fraud confirmed) **only exist for investigated claims**. Because only a fraction of claims are investigated, the observed fraud rate:

$$\hat{p}_{\text{observed}} = P(\text{fraud} | \text{investigated})$$

systematically overstates model effectiveness and understates true fraud prevalence. The SFP loop amplifies this: each model version narrows the investigated population further, making the biased sample even smaller.

Formally, the true fraud rate:

$$p_{\text{true}} = P(\text{fraud}|\text{inv}=1) \cdot P(\text{inv}=1) + P(\text{fraud}|\text{inv}=0) \cdot P(\text{inv}=0)$$

The second term is **permanently unobserved** in the standard SFP feedback architecture.

#### 2-3. Performance Metrics for Fraud Detection (§3.2)

Key recommendations, directly relevant to Build 03:
- **Cost-benefit models over accuracy**: False negatives (missed fraud) are far more costly than false positives. Allianz's Operations team should use monetary savings per investigation, not hit-rate.
- **AUC**: Threshold-independent. Only Viaene et al. (2004) maximised AUC in automobile insurance.
- **AMOC**: Activity Monitoring Operating Characteristic — suited to time-series monitoring of fraud.
- **Brier score / cross-entropy**: For probability calibration quality.

The paper warns that class labels can be "incorrect and subject to sample selectivity bias" (Hand, 2004; Brockett, 2002) — the formal statement of why standard AUC evaluation is unreliable under SFP.

#### 2-4. Detection Method Taxonomy (§4, Figure 4.1)

Four data categories (A = labelled fraud+legal; B = labelled legal only; C = unlabelled; D/E = evaluation instances):

| Category | Approach | Best Performers in Insurance |
|----------|----------|------------------------------|
| A+B+C+D | Supervised hybrid | AdaBoosted Naive Bayes (Viaene et al., 2004) |
| A+C | Supervised/Unsupervised hybrid | Signatures + supervised (Cortes & Pregibon, 2001) |
| C | Unsupervised | Clustering + anomaly detection |

Key critique (§4.6): Too much emphasis on complex non-linear models (SVM, NN). "In the long term, less complex and faster algorithms such as Naive Bayes and logistic regression will produce equal, if not better results on population-drifting, concept-drifting, adversarial-ridden data."

#### 2-5. Automobile Insurance Fraud Specifics

Binary indicator attributes (accident, claimant, driver, injury, treatment, lost wages, vehicle) make automobile insurance data well-suited to logistic regression and Naive Bayes. The Phua et al. (2004) dataset is the only small public automobile insurance dataset available for research — motivating synthetic data generation in the dissertation.

### 3. Direct Relevance to the Allianz SFP Project

#### 3-1. Build-Phase Contributions

| Phase | Contribution |
|-------|-------------|
| Build 00 EDA | Benchmark fraud rates (0.1%–10%); class imbalance severity; coverage gap (P(investigated) by segment) |
| Build 01 SFP Simulation | Three fraudster types generate different loop dynamics: average offenders are caught first; professional/organised survive loop iterations |
| Build 02 Detection | "Selective labelling + class label inaccuracy" = formal basis for SFP detection signals; segment blind-spot analysis identifies which claim_type/postcode_risk zones are under-investigated |
| Build 03 Unbiased Eval | Standard AUC over-estimates under selective labels; IPS-corrected metrics address the tip-of-the-iceberg gap |
| Build 04 Intervention | Concept drift = fraud pattern shifts over time; DiD and RDD address the explicit critique that "virtually no study uses temporal information" |
| Build 05 Randomisation | ε-greedy exploration counters adversarial adaptation by professional/organised fraudsters |
| Build 06 Causal Mitigation | IPW reweighting partially recovers the unobserved P(fraud|not investigated) term |

#### 3-2. SFP Loop Amplifies the Tip-of-Iceberg Gap

Over successive model versions:

| Model Version | P(investigated) | P(fraud\|inv=1) | True P(fraud) | Tip-of-Iceberg Gap |
|--------------|-----------------|-----------------|---------------|-------------------|
| v1 | 15% | 8% | ~12% | 4% |
| v2 | 12% | 9% | ~12% | 3% but widening |
| v3 | 9% | 11% | ~12% | Hidden 9% |

The observed metric (P(fraud|investigated)) rises, creating a false impression of model improvement. Build 01's simulation reproduces this pattern.

### 4. Limitations

- **2010 publication date**: Does not cover deep learning, graph neural networks, or LLM-based fraud detection.
- **Dominated by non-UK research**: Regulatory context (FCA Consumer Duty, UK GDPR) not addressed.
- **No SFP loop formalisation**: The paper identifies the selective-labelling problem but does not formalise the feedback mechanism as a self-fulfilling prophecy loop.
- **Unsolved adversarial dynamics**: Game-theoretic treatment of fraudster adaptation is acknowledged but not solved.

## 🎯 Interview Talking Points (P9-specific)

| Prompt | Use P9 to say… |
|--------|---------------|
| *"Why is insurance fraud detection particularly hard?"* | "Phua et al. (2010) identify two compounding problems. First, fraud rates are typically under 10% — sometimes 0.1% — creating severe class imbalance. Standard classifiers that output 'not fraud' for everything achieve 99.9% accuracy but zero utility. Second, labels only exist for investigated claims — which is a small fraction of all claims. This selective labelling means the training data is a biased sample, and the model is evaluated on its own filtered output. The SFP loop is what happens when these two problems interact across model retraining cycles." |
| *"What is the tip-of-the-iceberg problem?"* | "Phua et al. quantify it: the observed fraud rate in investigated claims systematically exceeds the true population fraud rate, because investigators are sent where the model predicts fraud. The undetected fraud — the bulk of the iceberg — is in the claims the model scored low. Over successive model versions, each one trained on the previous one's detections, the iceberg tip grows smaller relative to the hidden base. My Build 01 simulation makes this quantitative: by model v3, the observed fraud rate in the investigated cohort is 11% while the true rate is 12%, but the uninvestigated 91% of claims contain virtually no discovered fraud — creating a 91% gap." |
| *"How does fraudster type affect the SFP loop?"* | "Phua et al. (2010) classify fraudsters into average, criminal, and organised. Average opportunistic fraudsters are caught early — they don't adapt. But professional and organised fraudsters actively reverse-engineer the detection system. In the SFP context, after a few model generations, the average fraudsters have been suppressed and what remains is the adaptive professional and organised segment — exactly the ones hardest to detect. Build 01 simulates this by giving each synthetic fraudster type a different response elasticity to the model score." |
| *"Why don't standard AUC metrics catch the SFP loop?"* | "Because AUC is computed on the labelled dataset — and the labelled dataset is exactly the investigated subset. Phua et al. note that class labels can be 'subject to sample selectivity bias.' In the SFP setting, the AUC improves each model generation not because the model is genuinely better at finding fraud, but because it is increasingly evaluated only on the claims it already predicted as high-risk. Build 03's IPS-corrected AUC reweights each claim by the inverse of its investigation probability, recovering an approximately unbiased performance estimate." |
| *"Why do you generate synthetic data rather than use real Allianz data exclusively?"* | "Phua et al. (2010) document that there are essentially no publicly available insurance fraud datasets for benchmarking. The only exception is a small automobile insurance dataset from their own 2004 paper. This makes open-science replication impossible. I generate synthetic data following the five-step methodology of Barse et al. (2003) — which Phua et al. endorse — to create controlled scenarios where the true fraud label is known, so I can validate that my SFP detection and mitigation methods work before applying them to the real Allianz dataset." |
| *"What does the paper say about temporal data in fraud detection?"* | "One of Phua et al.'s strongest critiques (§4.6) is that 'virtually no fraud detection study explicitly uses temporal information.' The SFP loop is an inherently temporal phenomenon — it unfolds across model retraining cycles. My Build 02's temporal prediction correlation test (Step 1 of SFPDetector) directly addresses this gap by measuring how model scores across versions v1, v2, v3 correlate over time, using `claim_date` as the time axis." |
| *"How does the adversarial nature of fraud detection relate to your randomisation strategy?"* | "Phua et al. note that professional fraudsters 'continually supply new or modified styles of fraud until the detection systems start generating false negatives again.' ε-greedy randomisation (Build 05) counters this by making the investigation policy partially unpredictable — it introduces a random exploration probability ε that sends investigators to claims the model would otherwise ignore. This both closes the feedback loop (providing labels for low-scored claims) and makes the detection policy harder for adaptive fraudsters to exploit." |
| *"What performance metric does Allianz Operations care about most?"* | "Phua et al. emphasise that in insurance fraud, false negative and false positive costs are asymmetric and monetary. The Operations team cares about cost savings per investigation pound spent — equivalent to the paper's 'cost-benefit model' or 'benefit matrix' approach. Build 05's randomisation policy optimisation includes an explicit cost-benefit calculation: investigation cost versus expected fraud recovery amount, weighted by the model's posterior fraud probability." |
