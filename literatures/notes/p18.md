## 🇰🇷 한국어 요약

### 1. 문제 정의 — "Underspecification" (과소명세)

현대 ML 파이프라인은 **학습 데이터에서 동등한 성능을 내는 모델들**을 대량으로 생성하지만, 배포 환경에서는 그 모델들이 **크게 다르게 행동**한다. 이것이 논문이 말하는 **Underspecification(과소명세)** 문제다.

#### 공식 정의

ML 파이프라인이 *underspecified*라는 것은, 동일한 iid 성능을 내는 근사 최적 예측기의 집합 $\mathcal{F}^*$이 존재할 때, 이 집합 안에 **서로 상이한 귀납적 편향을 인코딩한 예측기들이 공존**하는 상황이다.

형식적으로:

$$\exists \; \theta_1, \theta_2 \in \mathcal{F}^* \quad \text{s.t.} \quad \mathcal{R}_P(\theta_1) \approx \mathcal{R}_P(\theta_2) \quad \text{but} \quad \mathcal{R}_{P'}(\theta_1) \gg \mathcal{R}_{P'}(\theta_2)$$

- $P$ = 학습(iid) 분포
- $P'$ = 배포 환경의 OOD(out-of-distribution) 분포
- $\mathcal{R}_P(f) = \mathbb{E}_{(X,Y) \sim P}[\ell(f(X), Y)]$ = 기대 예측 손실

**핵심 통찰:** iid 성능 기준으로는 $\theta_1$과 $\theta_2$를 구분할 수 없지만, 배포 환경에서는 한 쪽이 훨씬 나쁠 수 있다. 파이프라인은 이 둘 중 **임의로** 하나를 반환한다 — 초기화, 학습률 스케줄 같은 편의적 선택에 의해.

### 2. 핵심 개념

#### 2-1. Underspecification vs. Structural Failure Mode (구조적 실패)

| 구분 | Structural Failure | **Underspecification** |
|------|-------------------|----------------------|
| 원인 | iid 분포와 배포 분포 간 명시적 충돌 | iid 성능에서 동등한 모델들이 서로 다른 귀납적 편향을 인코딩 |
| 예측 | 두 동일 학습 모델이 같은 방식으로 실패 | **두 동일 학습 모델이 다르게 실패** — 이것이 핵심 관찰 |
| 해결 방법 | 더 많은 iid 데이터, 모델 아키텍처 수정 | **스트레스 테스트, 귀납적 편향 제약 조건 명시** |

#### 2-2. 스트레스 테스트 (Stress Test) — 과소명세 진단 도구

논문은 세 가지 유형의 스트레스 테스트를 정의한다:

1. **Stratified Performance Evaluation (계층화 성능 평가):** 특정 속성 $A$로 데이터를 층화하여 성능 계산. 예: 보험 청구 유형(`claim_type`) 별 AUC.
2. **Shifted Performance Evaluation (분포 이동 성능 평가):** 학습 분포 $P$와 다른 분포 $P'$에서 성능 측정. 예: 다른 연도, 지역, 채널에서의 성능.
3. **Contrastive Evaluation (대조 평가):** 입력 $x$에 대한 변환 집합 $\mathcal{T}$를 적용해 모델 출력이 예상대로 바뀌는지 확인. 예: 청구 금액을 소폭 변화시켰을 때 사기 점수가 단조 변화하는가.

#### 2-3. 세 가지 Warm-up 예시 (Section 3)

**예시 1 — SIR 역학 모델 (역학적 과소명세):**

$$\frac{dS}{dt} = -\beta\left(\frac{I}{N}\right)S, \quad \frac{dI}{dt} = -\frac{I}{D} + \beta\left(\frac{I}{N}\right)S, \quad \frac{dR}{dt} = \frac{I}{D}$$

초기 유행 단계에서 $(\beta, D)$의 서로 다른 값 쌍이 **동일한 성장률 $\beta - 1/D$**를 생성하므로, 학습 데이터만으로는 두 파라미터를 분리 불가능하다. 같은 학습 손실, 완전히 다른 유행 예측.

**예시 2 — 랜덤 피처 모델 (이론적 분석):**

$$f_{\mathbf{W}}(\mathbf{x}) = \boldsymbol{\theta}^\top \sigma(\mathbf{W}\mathbf{x})$$

$N/n \geq 1$ (과잉 매개변수화) 상황에서, OOD 일반화 오차의 이론적 상한이 존재하며, 이 오차는 **학습 데이터로 결정되지 않는 귀납적 편향**에 의존한다.

**예시 3 — 의학 유전체학 (실제 데이터):**

다각형 위험 점수(polygenic risk score) 학습 시, 서로 다른 민족 집단에서 성능이 크게 갈린다. 이는 iid 성능이 같더라도 유전자 상관 구조에 대한 귀납적 편향이 다르기 때문이다.

#### 4-3. 코드 구현 시사점

```python
# Build 03: unbiased_eval.py — 과소명세 진단을 위한 스트레스 테스트 구현

def stress_test_by_segment(df, model_score_col, label_col, segment_col):
    """
    Stratified stress test: 세그먼트별 AUC 편차 측정.
    과소명세 징후: 세그먼트 간 AUC 분산이 크면서 overall AUC는 높은 경우.
    """
    results = {}
    for seg_val in df[segment_col].unique():
        subset = df[df[segment_col] == seg_val]
        if subset[label_col].nunique() == 2:  # 라벨 존재 확인
            auc = roc_auc_score(subset[label_col], subset[model_score_col])
            results[seg_val] = {'auc': auc, 'n': len(subset),
                                'investigation_rate': subset['investigated'].mean()}
    return pd.DataFrame(results).T

# IPS-corrected AUC: 배포 분포 P'에서의 성능 추정
# = 과소명세 F*의 어느 원소인지를 드러내는 실질적 평가
def ips_corrected_auc(df, score_col, label_col, propensity_col):
    investigated = df[df['investigated'] == 1].copy()
    weights = 1.0 / investigated[propensity_col]
    return roc_auc_score(investigated[label_col], investigated[score_col],
                         sample_weight=weights)
```

### 5. 한계 (논문이 명시)

- **일반적인 처방 없음:** 과소명세의 존재를 보이는 것이 목표이며, 모든 케이스에서 작동하는 단일 해법은 없다.
- **스트레스 테스트의 설계 어려움:** 좋은 스트레스 테스트는 도메인 지식이 필요하다. 잘못 설계된 스트레스 테스트는 진짜 과소명세를 놓칠 수 있다.
- **귀납적 편향 명시화의 비용:** 추가 제약 조건을 부과하면 iid 성능이 저하될 수 있다는 우려가 있었으나, 논문은 이것이 불가피하지 않음을 시사한다.
- **iid 성능과의 트레이드오프 없음이 보장되지 않음:** 일부 도메인에서는 OOD 성능 향상을 위해 iid 성능을 희생해야 할 수 있다.
- **대형 모델에 특화:** 소형 모델 또는 단순 테이블 데이터에서도 같은 현상이 나타나는지는 충분히 연구되지 않았다.

## 🇬🇧 English Summary

### 1. Problem — What Is Underspecification?

An ML pipeline is **underspecified** when it can return many distinct predictors with equivalently good held-out performance on the training distribution, yet those predictors behave very differently when deployed. The paper formally defines this via the equivalence class of near-optimal predictors $\mathcal{F}^*$:

$$\exists \; \theta_1, \theta_2 \in \mathcal{F}^* \quad \text{s.t.} \quad \mathcal{R}_P(\theta_1) \approx \mathcal{R}_P(\theta_2) \quad \text{but} \quad \mathcal{R}_{P'}(\theta_1) \gg \mathcal{R}_{P'}(\theta_2)$$

where $P$ is the training distribution and $P'$ is an out-of-distribution (deployment) distribution. The pipeline returns an **arbitrary element** of $\mathcal{F}^*$, selected by convenience choices such as random seed, initialisation scheme, or learning rate schedule — none of which affect iid performance.

**Key distinction from structural failure modes:** Structural failures predict that two identically-trained models will fail the same way. Underspecification predicts that they may fail *differently*. This is the novel and practically important insight.

### 2. Technical Framework

#### 2-1. Stress Tests (Section 2.3)

The paper operationalises underspecification diagnosis through three stress test types:

- **Stratified evaluations:** Compute performance metric within strata defined by attribute $A$: $\mathcal{D}'_a = \{(x_i, y_i) : A_i = a\}$.
- **Shifted evaluations:** Test performance under a new data distribution $P' \neq P$ — e.g., a different time period, hospital, or geographic region.
- **Contrastive evaluations:** Apply a set of label-preserving transformations $\mathcal{T}$ to each input and check for unexpected output changes.

#### 2-2. Warm-up: Three Analytically Tractable Examples

**SIR Epidemiological Model (Section 3.1):**

The SIR system $(\beta, D)$ is underspecified during early epidemic phases because many parameter pairs yield the same exponential growth rate $\beta - 1/D$. Identical training loss, wildly divergent long-horizon forecasts. This is the simplest demonstration that underspecification is not a deep learning phenomenon — it arises in any overparameterised system.

**Random Feature Model (Section 3.2):**

For a one-hidden-layer network $f_{\mathbf{W}}(\mathbf{x}) = \boldsymbol{\theta}^\top \sigma(\mathbf{W}\mathbf{x})$ in the overparameterised regime ($N/n \geq 1$), the minimum $\ell_2$-norm interpolant selected by gradient descent encodes a specific inductive bias determined by the random feature matrix $\mathbf{W}$. The OOD generalisation error depends on this bias, not on iid performance.

**Genomics (Section 3.3):**

Polygenic risk score models trained with equivalent iid AUC show population-stratified performance divergence under demographic distribution shift — a critical equity concern with direct parallels to insurance segmentation fairness.

#### 2-3. Deep Learning Case Studies (Sections 5–8)

| Domain | Finding |
|--------|---------|
| Computer vision | Models with the same ImageNet AUC vary by up to 10 pp on ImageNet-C and ObjectNet — induced purely by random seed |
| Medical imaging (diabetic retinopathy) | Same training AUC, different grader-agreement performance — stress tests reveal which model to deploy |
| NLP | BERT-family models with identical STS benchmark scores diverge on contrastive and counterfactual evaluations |
| Electronic health records | Random seed change alone shifts temporal OOD AUC by several percentage points |

### 3. Direct Relevance to Allianz SFP Research

#### 3-1. Mapping to the Allianz Fraud Detection Context

In the Allianz setting, the iid training distribution $P$ is the **investigated claims** population (`investigated == 1`) — the only stratum with observed fraud labels. The OOD deployment distribution $P'$ is the **full claims portfolio** (all claims, investigated or not).

Underspecification materialises as follows: model versions v1, v2, v3 may all achieve high AUC on the investigated subset, while encoding completely different inductive biases about uninvestigated segments. The SFP loop *amplifies* this: each model version's investigation decisions determine what labels exist for the next training cycle, locking in and reinforcing a particular arbitrary element of $\mathcal{F}^*$.

#### 3-2. Build-phase Contributions

| Phase | D'Amour et al.'s Contribution |
|-------|------------------------------|
| Build 00 (EDA) | Stratified investigation rate by `claim_type`, `postcode_risk`, `product_line` — which strata are near-zero investigation rate? These are OOD regions for the model. |
| Build 02 (SFP Detector) | High temporal correlation between model scores (Step 1) is a sign that underspecification is compounding: successive $\mathcal{F}^*$ elements are converging to the same biased corner. |
| **Build 03 (Unbiased Eval)** | **This paper motivates the entire Build 03 design.** Standard AUC on training data is an $\mathcal{R}_P$ estimate. IPS-corrected AUC approximates $\mathcal{R}_{P'}$. The gap between them is a measure of underspecification severity. |
| Build 05 (Randomisation) | Randomised investigation of under-investigated segments is equivalent to performing a shifted performance evaluation under a more uniform $P'$ — directly testing which $\mathcal{F}^*$ element the model actually is. |
| Build 06 (Causal Mitigation) | IPW re-weighting shifts effective training distribution toward $P'$ — resolving underspecification by specifying a target inductive bias (favour the full portfolio, not just the investigated subset). |

### 4. Limitations

- No universal fix: the paper diagnoses the problem systematically but does not prescribe a domain-agnostic solution.
- Stress test design requires domain expertise — a poorly chosen stress test misses the relevant underspecification.
- The paper focuses on deep learning at scale; whether the findings generalise to gradient-boosted trees (LightGBM as in Build 01–06) is not directly tested, though the mechanism is architecture-agnostic in principle.
- The equivalence class $\mathcal{F}^*$ is theoretical — in practice, enumerating it to choose the "best" element is intractable without explicitly specified constraints.

The gap between them measures how severely the pipeline is underspecified. A large gap means the model that 'won' training might be arbitrarily bad on uninvestigated segments." |
| *"How does underspecification relate to fairness and FCA Consumer Duty?"* | "The paper explicitly notes that underspecification leads to disparate OOD performance across demographic or geographic strata. In the Allianz context, certain postcode risk bands or claim types may be systematically underserved — the model's arbitrary inductive bias happens to work well for the investigated majority but fails for uninvestigated minorities. This is precisely the kind of unfair outcome that FCA's Consumer Duty targets." |
| *"What is the fix for underspecification?"* | "The paper advocates explicitly specifying the required inductive biases as constraints on F*. In our case, that means: the model should perform adequately on all claim segments, not just investigated ones. Build 05 operationalises this by randomising a fraction of investigations — it forces the pipeline to sample from P' rather than the biased P, producing training data that narrows F* toward the intended corner." |
| *"Can underspecification be solved by ensembling?"* | "The paper warns that naively averaging across F* is not guaranteed to help — in fact some predictors in F* generalise poorly in new domains, and averaging them may not produce something in the 'good' corner of F*. Application-specific constraints (like causal DAG requirements from DoWhy in Build 06) are a more principled route." |
| *"How does this paper relate to the other papers in your dissertation?"* | "P1 (Lakkaraju KDD'17) identifies selective labels as the mechanism creating the biased training distribution P. P18 (D'Amour JMLR'22) explains why this biased P produces underspecified models — many F* candidates trained on investigated claims behave differently on the full portfolio. Together they provide the full diagnosis: selective labels create P, P produces underspecification in F*, the SFP loop compounds underspecification across model versions. Build 03 addresses this with IPS; Build 06 addresses it with IPW re-weighting." |
